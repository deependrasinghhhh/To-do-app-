# To-do-app-

A small full-stack todo app for learning Java and Spring Boot. It has a browser UI, a JSON REST API, a file-based H2 database, validation, and a few tests—without requiring a separate frontend or database installation.

## What you will learn

- How Spring Boot starts a web server from a `main` method
- How a controller exposes HTTP endpoints
- How a service holds application rules
- How JPA maps a Java class to a database table
- How validation keeps bad request data out
- How a browser calls a REST API with `fetch`

## Run it

You already have a compatible JDK installed. From PowerShell:

```powershell
cd C:\CCST-2026\todo-app
.\mvnw.cmd spring-boot:run
```

On its first run, `mvnw.cmd` downloads Maven for this project, then Maven downloads the Spring dependencies. You do **not** need to install Maven globally.

Open <http://localhost:8080> in your browser. Stop the app with `Ctrl+C` in the terminal.

For macOS/Linux:

```bash
cd todo-app
chmod +x mvnw
./mvnw spring-boot:run
```

## Try the API

The UI uses these same endpoints. You can also call them directly from PowerShell with `curl.exe`.

| Method | URL | What it does |
| --- | --- | --- |
| `GET` | `/api/todos` | List todos |
| `GET` | `/api/todos/{id}` | Get one todo |
| `POST` | `/api/todos` | Create a todo |
| `PATCH` | `/api/todos/{id}` | Change its title, completion state, due date, priority, category, or description |
| `DELETE` | `/api/todos/{id}` | Delete a todo |

```powershell
# Create a todo
curl.exe -X POST http://localhost:8080/api/todos `
  -H "Content-Type: application/json" `
  -d '{"title":"Learn Spring Boot"}'

# List todos
curl.exe http://localhost:8080/api/todos

# Mark todo 1 complete
curl.exe -X PATCH http://localhost:8080/api/todos/1 `
  -H "Content-Type: application/json" `
  -d '{"completed":true}'

# Rename todo 1
curl.exe -X PATCH http://localhost:8080/api/todos/1 `
  -H "Content-Type: application/json" `
  -d '{"title":"Build a Spring Boot app"}'

# Delete todo 1
curl.exe -X DELETE http://localhost:8080/api/todos/1
```

Successful creation returns HTTP `201`; invalid titles return `400`; an unknown ID returns `404`.

## Project map

```text
src/main/java/com/example/todo/
├── TodoApplication.java       # Starts Spring Boot and embedded Tomcat
└── todo/
    ├── Todo.java              # JPA entity → the todos database table
    ├── TodoRepository.java    # Database operations generated by Spring Data
    ├── TodoService.java       # Create, read, update, delete use cases
    ├── TodoController.java    # HTTP/JSON endpoints under /api/todos
    ├── *Request.java          # Input validation and request shapes
    ├── TodoResponse.java      # JSON returned to callers
    └── ApiExceptionHandler.java

src/main/resources/
├── application.properties     # H2 database configuration
└── static/                    # The small browser UI: HTML, CSS, and JavaScript
```

When a browser creates a todo, the path is:

```text
Browser form → TodoController → TodoService → TodoRepository → H2 database
                                                    ↓
Browser receives JSON ← TodoResponse ←─────────────┘
```

Spring finds these pieces because `@SpringBootApplication` scans the `com.example.todo` package. It creates and connects the controller, service, and repository for you through constructor injection.

## Database

The app uses H2, a small embedded database. Data is stored under `data/` beside the project, so your todos remain after an app restart. That folder is ignored by Git.

While the app is running, you can inspect the database at <http://localhost:8080/h2-console>:

- JDBC URL: `jdbc:h2:file:./data/todo-db`
- User name: `sa`
- Password: leave blank

The H2 console is enabled only to help you learn locally; do not expose it in a production app.

## Run the tests

```powershell
.\mvnw.cmd test
```

The project includes:

- `TodoServiceTest` — fast unit tests using a mocked repository
- `TodoApplicationTests` — starts Spring with an in-memory H2 database, verifies persistence, and checks the HTTP API's success and error responses

## Good next exercises

1. Add a `dueDate` field to `Todo`, the request/response records, UI, and tests.
2. Add a `GET /api/todos?completed=false` filter in the repository and controller.
3. Add a `createdAt` timestamp that is set when a todo is created.
4. Replace H2 with PostgreSQL and add Flyway database migrations.
5. Add login/authentication only after the core API feels comfortable.

Start by following one request through the files in the project map. Reading the code in that order is usually the easiest way to see how Spring Boot fits together.
